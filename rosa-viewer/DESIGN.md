# Rosa Viewer Design Document

## Overview

Rosa Viewer is a JavaScript web application for browsing and viewing digitized books from archives managed by rosa-tool. It is built on Mirador 4, a IIIF-compliant viewer, with custom plugins that provide search and browse functionality powered by Opensearch.

The viewer is compiled into a static website and deployed alongside IIIF Presentation API files and an Opensearch index generated by rosa-tool.

## Configuration

### Plugin Configuration Schema

The JHSearch plugin is configured through Mirador's initialization config:

```javascript
Mirador.viewer({
  id: 'rosa-viewer',
  // ... standard Mirador config
  jhsearch: {
    // Required: Base URL for IIIF Presentation API
    iiifBaseUrl: 'https://iiif.example.org',
    
    // Required: Top-level collection ID
    collectionId: 'rose',
    
    // Optional: Child collection IDs (if hierarchy exists)
    childCollectionIds: ['subcollection1', 'subcollection2'],
    
    // Optional: IIIF Image API base URL for thumbnails
    imageBaseUrl: 'https://image.example.org/iiif',
    
    // Optional: Thumbnail URL template
    // Available placeholders: {imageBaseUrl}, {iiifImageId}, {width}
    thumbnailTemplate: '{imageBaseUrl}/{iiifImageId}/full/{width},/0/default.jpg',
    
    // Optional: Default thumbnail width in pixels
    thumbnailWidth: 80,
    
    // Optional: Base URL for collection logos
    logoBaseUrl: '/logo',
    
    // Optional: Enable/disable faceted browsing (default: true)
    enableFacets: true,
    
    // Optional: Default page size for results
    pageSize: 20,
    
    // Optional: Available page size options
    pageSizeOptions: [20, 30, 40, 50],
  }
}, [
  ...jhsearchPlugin,
]);
```

### Configuration Resolution

On initialization, the plugin:

1. Loads `{iiifBaseUrl}/{collectionId}/collection.json`
2. Extracts the `JHSearchService2` service block to get the jhsearch.json URL
3. Fetches the jhsearch.json which is the id of the service to obtain:
   - Available search fields and their metadata
   - Category definitions for faceted browsing
   - Default search fields
   - Opensearch endpoint URL
4. Queries Opensearch with aggregation on `collection_id` to build the collection hierarchy

### Component Specifications

#### JHSearchView

The main container that replaces Mirador's default WorkspaceAdd component.

**Props (from Redux):**
- `config` - Plugin configuration
- `service` - JHSearch service data
- `collections` - Collection hierarchy
- `error` - Any error state

**Behavior:**
- Shows loading spinner during initialization
- Shows error message if configuration fails to load
- Renders sidebar and main content area when loaded

```jsx
<JHSearchView>
  <JHSearchSidebar />
  <SearchResults />
</JHSearchView>
```

#### JHSearchSidebar

**Sections:**
1. **Collection Selector** (if child collections exist)
2. **Category Facets** (if `enableFacets: true`)
3. **Simple Search**
4. **Advanced Search** (expandable)
5. **Sort Order**
6. **Clear Button**

#### CollectionSelector

A dropdown showing the collection hierarchy with logos.

**Data Source:** Opensearch aggregation on `collection_id` field, cross-referenced with IIIF collection.json for labels and logos.

**Behavior:**
- Defaults to top-level collection
- Shows tree structure for nested collections
- Each entry displays collection logo (from `{logoBaseUrl}/{logo}`) and label
- Hidden if top-level collection has no children

#### CategoryFacets

Displays facet categories defined in jhsearch.json.

**For each category:**
- Category label as header
- List of values with counts (from Opensearch aggregation)
- Checkbox for multi-select
- Selected values highlighted and removable

**Logic:**
- Multiple values within a category = OR
- Multiple categories selected = AND
- Facet counts update based on current selections

#### SimpleSearch

A single text input that searches across default fields.

**Behavior:**
- Searches fields listed in `default-fields` from jhsearch.json
- Uses `multi_match` query with subfield expansion
- Triggers search on Enter or button click

#### AdvancedSearch

A form allowing field-specific searches with boolean logic.

**Features:**
- Add/remove field rows
- Each row has:
  - Field dropdown (from jhsearch.json `fields`)
  - Value input (text input or dropdown for fields with `values`)
  - AND/OR operator selector (relative to previous row)
- Field help tooltips using `description` from jhsearch.json
- For fields with `values` array, show dropdown instead of text input

#### SearchResults

Displays browse or search results.

**Browse Mode (no search query):**
- Shows manifests filtered by selected collection and facets
- One manifest per row:
  - Collection logo
  - Manifest label
  - Number of images
  - First 3 thumbnails (after flyleaf, using `thumbnail` field from manifest index)

**Search Mode:**
- Shows matching manifests and canvases
- One result per row:
  - Thumbnail (single)
  - Label (manifest label or canvas label)
  - Highlighted matching fields
  - Result type indicator (Book/Page)

**Thumbnail Loading:**
- Use Intersection Observer to lazy-load thumbnails
- Only request thumbnails visible in viewport
- Prevents overwhelming the image server

**Click Behavior:**
- Manifest click: Opens manifest in Mirador page-turner view
- Canvas click: Opens manifest at specific canvas in Mirador

#### Pagination

Standard pagination controls.

**Features:**
- Page size selector (20, 30, 40, 50)
- Previous/Next buttons
- Page number display
- Total results count

**Behavior:**
- New page replaces current results
- Scrolls to top of results on page change

#### SortOrder

Dropdown for result ordering.

**Options:**
- Relevance (default, `_score` desc)
- Page Order (`page_num` asc) - only meaningful for canvas results

#### ErrorDisplay

Displays when Opensearch is unavailable.

**Content:**
- Error message explaining search is unavailable
- Disables all search/browse controls
- Shows retry option (page refresh)

### Opensearch Query Construction

#### Browse Query (no search terms)

```javascript
function buildBrowseQuery({ collectionId, facets, page, pageSize }) {
  const query = {
    bool: {
      filter: [
        { terms: { collection_id: [collectionId] } }
      ]
    }
  };
  
  // Add facet filters (AND between categories, OR within category)
  for (const [category, values] of Object.entries(facets)) {
    if (values.length > 0) {
      query.bool.filter.push({
        terms: { [category]: values }
      });
    }
  }
  
  return {
    query,
    from: page * pageSize,
    size: pageSize,
    aggs: buildFacetAggregations(categories),
  };
}
```

#### Simple Search Query

```javascript
function buildSimpleSearchQuery({ query, defaultFields, collectionId, facets, page, pageSize }) {
  // Expand fields with subfields
  const searchFields = expandFieldsWithSubfields(defaultFields, fields);
  
  return {
    query: {
      bool: {
        must: [
          {
            multi_match: {
              query,
              fields: searchFields,
              type: 'best_fields',
            }
          }
        ],
        filter: [
          { terms: { collection_id: [collectionId] } },
          ...buildFacetFilters(facets),
        ]
      }
    },
    from: page * pageSize,
    size: pageSize,
    highlight: {
      fields: buildHighlightFields(searchFields),
      pre_tags: ['<mark>'],
      post_tags: ['</mark>'],
    },
    aggs: buildFacetAggregations(categories),
  };
}
```

#### Advanced Search Query

```javascript
function buildAdvancedSearchQuery({ rows, collectionId, facets, page, pageSize }) {
  // Build clause array from rows
  const clauses = rows.map((row, index) => {
    const fieldSpec = fields.find(f => f.name === row.field);
    const searchFields = fieldSpec.subfields 
      ? fieldSpec.subfields.map(sf => `${row.field}.${sf}`)
      : [row.field];
    
    return {
      multi_match: {
        query: row.value,
        fields: searchFields,
        type: 'best_fields',
      }
    };
  });
  
  // Combine with operators (first row has no operator, subsequent rows use AND/OR)
  const must = [];
  const should = [];
  
  clauses.forEach((clause, index) => {
    if (index === 0 || rows[index].operator === 'AND') {
      must.push(clause);
    } else {
      should.push(clause);
    }
  });
  
  return {
    query: {
      bool: {
        must,
        should,
        minimum_should_match: should.length > 0 ? 1 : 0,
        filter: [
          { terms: { collection_id: [collectionId] } },
          ...buildFacetFilters(facets),
        ]
      }
    },
    from: page * pageSize,
    size: pageSize,
    highlight: {
      fields: buildHighlightFields(getAllSearchFields(rows)),
      pre_tags: ['<mark>'],
      post_tags: ['</mark>'],
    },
    aggs: buildFacetAggregations(categories),
  };
}
```

#### Field Expansion for multi_match

Fields with subfields must be expanded for proper multi_match queries:

```javascript
function expandFieldsWithSubfields(fieldNames, fieldDefinitions) {
  const expanded = [];
  
  for (const name of fieldNames) {
    const fieldDef = fieldDefinitions.find(f => f.name === name);
    if (fieldDef?.subfields) {
      // Expand to all subfields: marginalia -> marginalia.en, marginalia.fr, etc.
      for (const subfield of fieldDef.subfields) {
        expanded.push(`${name}.${subfield}`);
      }
    } else {
      expanded.push(name);
    }
  }
  
  return expanded;
}
```

### URL Construction

#### Thumbnail URLs

```javascript
function buildThumbnailUrl(iiifImageId, config) {
  const encoded = encodeURIComponent(iiifImageId).replace(/%2F/g, '%2F');
  
  return config.thumbnailTemplate
    .replace('{imageBaseUrl}', config.imageBaseUrl)
    .replace('{iiifImageId}', encoded)
    .replace('{width}', config.thumbnailWidth);
}
```

Default template: `{imageBaseUrl}/{iiifImageId}/full/{width},/0/default.jpg`

#### IIIF Manifest URLs

```javascript
function buildManifestUrl(manifestId, iiifBaseUrl) {
  // manifestId format: "collection.book" e.g., "rose.Douce195"
  const [collectionId, bookId] = manifestId.split('.');
  return `${iiifBaseUrl}/${collectionId}/${bookId}/manifest.json`;
}
```

#### IIIF Canvas URLs

```javascript
function buildCanvasUrl(manifestId, pageNum, iiifBaseUrl) {
  const [collectionId, bookId] = manifestId.split('.');
  return `${iiifBaseUrl}/${collectionId}/${bookId}/canvas/${pageNum}`;
}
```

#### Logo URLs

```javascript
function buildLogoUrl(logo, logoBaseUrl) {
  return `${logoBaseUrl}/${logo}`;
}
```

### Navigation Integration

#### Opening a Manifest

When user clicks a manifest result:

```javascript
function openManifest(manifestId, iiifBaseUrl, dispatch) {
  const manifestUrl = buildManifestUrl(manifestId, iiifBaseUrl);
  
  // Use Mirador's action to add a window with the manifest
  dispatch({
    type: 'mirador/ADD_WINDOW',
    window: {
      manifestId: manifestUrl,
    },
  });
}
```

#### Opening a Canvas

When user clicks a canvas result:

```javascript
function openCanvas(manifestId, pageNum, iiifBaseUrl, dispatch) {
  const manifestUrl = buildManifestUrl(manifestId, iiifBaseUrl);
  const canvasUrl = buildCanvasUrl(manifestId, pageNum, iiifBaseUrl);
  
  dispatch({
    type: 'mirador/ADD_WINDOW',
    window: {
      manifestId: manifestUrl,
      canvasId: canvasUrl,
    },
  });
}
```

## Error Handling

### Initialization Errors

If IIIF collection.json or jhsearch.json cannot be loaded:
- Display error message in main view area
- Disable all search/browse controls
- Log detailed error to console

### Search Errors

If Opensearch query fails:
- Display error message in results area
- Preserve current UI state (facets, search terms)
- Allow retry

### Network Resilience

- Use appropriate timeouts for all fetch requests
- Handle network errors gracefully
- Provide meaningful error messages to users

- IIIF Presentation API files (from rosa-tool `generate-iiif-pres`)
- Opensearch service with manifest and canvas indexes

- `index.html`

1. Build rosa-viewer
2. Copy `dist/` to deployment location
3. Configure the viewer with appropriate URLs for the deployment environment

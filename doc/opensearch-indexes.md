# Opensearch Index Design

## Purpose

This document describes the Opensearch index structure used by rosa2 for full-text and faceted search over manuscript collection data. It covers the three indexes, their field mappings, the multi-language text analysis strategy, and how to create indexes from the definition files.

## Audience

System administrators deploying the search infrastructure and developers working on search integration.

## Indexes

The system uses three indexes, each defined in `opensearch/` at the repository root:

| Index | Definition File | Description |
|-------|----------------|-------------|
| `manifest` | `opensearch/manifest.json` | One document per book — metadata, identifiers, facet fields |
| `canvas` | `opensearch/canvas.json` | One document per page — page-level identifiers and position |
| `annotation` | `opensearch/annotation.json` | One document per annotation — text content routed by language |

## Creating Indexes

Use the Opensearch REST API with the definition files:

```bash
curl -X PUT "https://<host>:9200/manifest" \
  -H "Content-Type: application/json" \
  -d @opensearch/manifest.json

curl -X PUT "https://<host>:9200/canvas" \
  -H "Content-Type: application/json" \
  -d @opensearch/canvas.json

curl -X PUT "https://<host>:9200/annotation" \
  -H "Content-Type: application/json" \
  -d @opensearch/annotation.json
```

After creating indexes, ingest bulk files generated by the `generate-opensearch-ingest` command:

```bash
curl -X POST "https://<host>:9200/_bulk" \
  -H "Content-Type: application/x-ndjson" \
  --data-binary @output/aor.bulk.json
```

## Multi-Language Field Structure

Textual annotation content is routed into language-specific sub-fields so that the correct analyzer (stemming, stop words) is applied at index time.

Supported languages and their sub-field suffixes:

| Language | Sub-field | Analyzer |
|----------|-----------|----------|
| English | `.en` | Standard English with stemming |
| French | `.fr` | French with stemming |
| Old French | `.ofr` | Custom: French stemming + asciifolding for spelling variation |
| Italian | `.it` | Italian with stemming |
| Latin | `.la` | Custom Latin stemming |
| Greek | `.el` | Greek analyzer |
| Spanish | `.es` | Spanish with stemming |
| German | `.de` | German with stemming |

This pattern applies to the following fields in the `annotation` index: `text`, `translation`, `emphasis`, `cross_reference`, and `anchor_text`.

The `manifest` index also has a multi-field `title` with language sub-fields for language-appropriate title search.

If an annotation's language code is not in the supported set, content falls back to the `.en` sub-field.

## Bulk Ingest File Format

Generated bulk files use the Opensearch Bulk API format — alternating action and document lines (newline-delimited JSON):

```json
{"index":{"_index":"annotations","_id":"aor/Ha2/Ha2.001r/marginalia_1"}}
{"id":"aor/Ha2/Ha2.001r/marginalia_1","type":"marginalia","text":{"la":"verbum"},...}
```

One bulk file is produced per collection, named `<collection-id>.bulk.json`.
